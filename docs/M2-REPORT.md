## 2. 真实语料驱动的门控演化(M2 最重要的工程记录)

用桌面简历 PDF 实测时,合成语料掩盖的问题全部暴露。三天内三轮修正,每轮都有量化依据:

| 轮次 | 发现 | 修正 |
|---|---|---|
| ① | 简历解析文本干净,但事实题仅 37.5%——**0.45 硬门控把换了措辞的有效问题全拦了**("候选人"vs"王安畅"、"教育背景"vs"教育程度") | 引入低置信档:0.18~0.45 回答带"⚠️ 低置信"免责声明+引用 |
| ② | 仍有 3 条硬拒答;逐字排查发现 **IDF 字符覆盖被"措辞字"反噬**——"候选/间/做"df=0 权重最大,而承载答案的"云深/科技/实习"太常见权重趋零;且答案 chunk 常不在 top1 | 覆盖度改按 **top3 证据集联合**计算 |
| ③ | union 覆盖救回了真实问题,却把 3 条无答案问题垫高成自信回答(CSV 表头效应);RN02 靠"通过"误放行 | confident 档回到**单 chunk** 覆盖;新增**短语级证据**(信息双字真实出现→低置信档)+ 短语停用表("通过/是否/进行") |

最终三档语义:`confident`(单 chunk 覆盖 ≥0.45 或 ≥2 个拉丁词)/ `low`(部分覆盖或短语级证据,必须带免责声明)/ `abstain`(空结果、未知词、无任何短语证据)。`/api/chat` 响应新增 `confidence` 字段,事件日志记录档位。

## 4. 已知边界

1. **无 key 的本地摘要是抽取式的**:答案 = 检索 top4 摘录(已加长到 480 字),不是生成式综合;配置模型 key 后走 LLM 路径(prompt 已带"只依据来源/不足即说明"约束)。
2. **实体抽取只覆盖拉丁词**:中文实体(如"风险核验助手")需要分词或 LLM,未引入依赖,如实留白;lint 的 duplicate_entity 检查已为将来自动页+手工页并存做准备。
3. **conflict_surfaced 是涌现行为**(两口径进 top4 摘要),专门的矛盾检测/标注仍是 M3+ 议题。
4. **低置信档比例偏高**(合成集 60% 无答案问题落在 low 档):比"自信的垃圾"诚实,但档位边界(0.18/0.45)是按当前 65 个用例校准的,语料增长后需重校。
5. 文件镜像在事务提交前写入,极端情况下可能短暂超前于库,下次 rebuild 收敛(已在代码注释声明)。
